# Failure test: cmp1

Started 2026-10-19 16:45. Power cut with `echo o > /proc/sysrq-trigger` (no sync, no clean shutdown); power restored with Hyper-V `Start-VM`.

## Findings

- Data written inside ledger before the failure is intact after evacuation (md5 82380afc8c91db8ee1b87f32e7b64c54).
- RADOS objects written before and during the failure read back with matching md5 after recovery.
- ledger was down from the power cut until it answered ping again on cmp2 (see timeline); Nova does not evacuate on its own.

## Operator notes

- **Downtime of the VM on the failed host:** 113 s from power cut to ping on the new host: 59 s for Nova to notice, 21 s to rebuild, 14 s waiting in SHUTOFF until started (Compute API 2.95+ keeps evacuated servers stopped), 19 s boot.
- **Storage:** Ceph marked the OSD down after 28 s and kept accepting writes with 2 of 3 copies. After the node returned, the cluster was clean 12 s after the OSD came up.
- **Earlier run (same day):** `openstack server evacuate --wait` waited forever because the server stays SHUTOFF; the script now starts it explicitly. Moving the server back with live migration failed once with `DestinationDiskExists`, then succeeded on retry (see the compute runbook).
